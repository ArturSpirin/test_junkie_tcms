# Changelog

## Unreleased
- Migrations: `audit_request_tool_agent_names` is now revision `0019` on top of `0018_product_owner_cycle_eta_order`, so `upgrade head` has one head again.
- CI: the test job runs the suites even when its lint step fails (the job still fails), and skips them only when install failed.
- `python scripts/check.py` runs the CI gate (ruff check, ruff format --check with the locked ruff, then every suite); CI's test job calls it, and `--lint` runs only the ruff steps.
- Products, features, plans, members and consumers lists take a `q` name search that holds across pages; a product has an owner (`owner_actor_id`, an active member) and can copy another product's feature tree on create (`copy_features_from`); starting a cycle takes an `eta`, an `order` and a manual `case_order`, read back on the cycle, and `cycle_cases_list?sort=position` lists the run order. Migration `0018`.
- Every response carries an `X-Request-ID`, and audit rows record it as `request_id`, plus `tool` for rows an MCP tool call wrote; `q` finds both. Agent names are lowercase letters, digits and single dashes, unique among an org's agents (409); migration `0019` renames existing agents to fit.
- Cases have a versioned `description`, in CSV and md-bundle files and in text search; `GET`/`PUT /cases/{case}/markdown` read and save one case as a Markdown file; each plan entry shows `cases` and `new_cases`. Migration `0017`. Two new MCP tools.
- Members can read an actor directory (`GET /actors`: names of users, agents, consumers and tokens); case versions record `via`, token and on-behalf-of; `GET /cases/{case}/cycles` lists a case's cycles; members and agents show `last_active_at`; agents take a `description` and can be re-enabled; audit filters by `actor_kind` and `q`, and `GET /audit/retention` states the policy and the oldest row kept.
- Every API time input (`since`, `until`, `updated_since`, `expires_at`, `released_at`) given in another zone is read as the same instant in UTC, so MCP stats buckets start at UTC midnight and echo `Z`; org, member, agent, token and audit times also come back in UTC on SQLite.
- Migrations: `result_case_version` is now revision `0015` on top of `0014_consumer_f7`, so `upgrade head` has one head again.
- Web app: the narrow-width Menu button says whether the menu is open (`aria-expanded`) and which nav it opens (`aria-controls`).
- Reports take a period (`from`, `to`, `tz`; default the last 30 days) and return a daily `trend`; release and feature rows add KPIs, drift and a `verdict`; the org report adds KPIs and per-product rows; the product report adds `whole`, the product as it stands; the feature report adds `last_result`, defects and the last 5 cycles as `history`. All additive to `/api/v1`.
- A cycle case edited after it has results can be refreshed to the current case version and rerun in the same cycle (no more `409 has_results`); each result records the case version it ran (`case_version`), release and feature reports keep a stale case's last result, and the cycle report counts its `stale` cases.
- Consumers: `consumers_jobs` lists a machine's jobs, which keep a `reason`; a machine can reject a job with a reason (its open cases cancel); admins can pause and resume a consumer, or pair it paused; admins can preview (`pairings_get`) and deny (`pairings_deny`) a pending pairing; `consumers_roster` lists the inventory refs with their linked case. The detail adds jobs and rejected in the last 24 h and tests found and linked.
- Web app: toasts, hints, query lines and the reports header no longer show API or MCP operation names; they use plain words, and server error text still shows as sent. The render test that guarded dialog footers now checks every rendered view state.
- On a Postgres server whose time zone isn't UTC, every time the API returns is now UTC (`+00:00`), as on SQLite, and MCP stats day buckets start at UTC midnight.
- Feature tree: the drag-and-drop hint bar now overlays the search row instead of pushing the tree down, so a drop lands on the row under the pointer.
- MCP `tools/call` on a tool the caller can't use now says why: 403 `Needs scope <scope>`, or 403 naming its toolset and `?toolsets=`; only a name that isn't a tool is 404 `Unknown tool`.
- MCP tools list each tool's description, its idempotent and destructive hints and its errors by HTTP status (`errors_by_code`); new `mcp_calls` lists the org's recent MCP calls (kept 7 days) with status and latency.
- Lists return `total`; products show `feature_count` and `case_count`, feature tree nodes `case_count` and `total_case_count`. The cases list filters by last result, priority, updated since, editor and automation ref, sorts (manual, key, title, updated, result, priority) and its `q` matches keys and steps; cases have a `position` that `cases_move` reorders. SQLite migrations run with foreign keys off and check them after.
- Web app top bar: the search is a labelled input ("Search cases"). `/` focuses it, except while you type in another field or a dialog is open, or when the search is hidden on narrow screens. Enter opens the cases view with `?q=`, which filters the cases it shows, and "Clear search" drops `q`.
- Web app screens, static for now: the 16 app views (products, releases, feature tree, cases, case editor, versions, plans, cycles, start run, run, reports, members, tokens, audit, MCP, consumers) as vanilla ES modules in `src/test_junkie_tcms/web/` with no build step. Every view reads its data through one module, `js/data.js`, which the API wiring replaces. Tests render every state under node (CI pins node; no npm).
- Web app shell: `web/` ships as package data, is served at `/assets/`, and `/` and `/app/...` return `index.html`; `docs/app-api-contract.md` lists the API each view uses. Plan status shows its enum on reads; consumers show `project_count`; MCP tools and usage take `since`/`until`, usage splits reads and writes, and new `mcp_clients` and `mcp_updates` list callers and server starts and tool-list changes.
- Bulk results take `comment` as `{"markdown"}` or `{"doc"}`, like a single result; a plain string is now a 422. Each bulk comment's cap moves from 20,000 characters to the single-result limit (200,000 for Markdown).
- README lists what this release has and documents the MCP endpoint and toolsets; a test keeps it in step with the toolsets and settings.
- Case titles are stripped of leading and trailing spaces, and a title of only spaces is a 422 on create, update, bulk, CSV and Markdown import, and MCP.
- Names (products, features, releases, plans, cycles, orgs, members, agents, tokens, invites, consumers) are stripped the same way, and a name of only spaces is a 422; CSV and Markdown import strip each feature path segment, so a path with extra spaces finds the existing feature.
- Quick start works on Windows: `requirements.lock` is now made by `scripts/lock.py` (uv, universal, with platform markers, checked in CI), and `create-admin` and `sweep-idempotency` apply migrations first.
- Scaffold: orgs, users, roles, scoped API tokens, session login with CSRF, append-only audit log and outbox; Docker Compose and CI.
- Catalog: products, feature trees, releases and test plans over the API, with rich text read and written as Markdown.
- Test cases: every edit saves an immutable version; `If-Match` on case edits, optional `Idempotency-Key` on POSTs; plans name cases and resolve to them. Cycle and plan case refs take a case key (`PAY-12`) or an id.
- Consumers: device-code pairing, consumer-scoped tokens, list/get/rename/revoke, heartbeats with derived online/offline status, and per-project inventory upload by hash.
- Member invites (7-day, single-use token shown once and stored hashed); audit log filters by `via`, `action` and `until`.
- Test plans: new plans start as `draft` (moves `draft → active → archived`, `archived → active`); archived plans are read-only; add a release's features as entries; reorder entries; feature list shows the last editor.
- Invitees with no account sign up on accept (`token`, `name`, `password`): user, membership and session in one transaction.
- `sweep-idempotency` command deletes expired `Idempotency-Key` records in batches; a reused expired key is claimed atomically.
- Execution: cycles pinned to the case version they run, bulk cycles by release in one batch, append-only results with per-step status, and attachments (raw or base64 upload, org-scoped content-addressed storage).
- MCP server at `/mcp` (and `test-junkie-tcms mcp` stdio bridge): tools generated from `@operation` routes, plugin routes included, default toolsets `core,cases,execution` (21 tools, setting `mcp_default_toolsets`), drift-guard test. New pins `mcp==2.3.0` and `httpx2==2.16.0`: `mcp` requires `httpx2`, which only the MCP dispatcher imports; the API and its tests keep `httpx`.
- Automated runs: cycles in `automated` or `both` mode send automated cases to chosen online consumers as jobs; consumers long-poll, claim and report; jobs can be cancelled or reassigned, and a stalled job is requeued once, then its cases cancel. New MCP tools `jobs_list`, `jobs_cancel` and `jobs_reassign` (`execution` toolset; the default toolsets now list 24 tools).
- MCP page stats: each `/mcp` call adds to an hourly `mcp_tool_stat` row (calls, errors, response sizes); `mcp_tools_list`, `mcp_usage` and `mcp_server_get` give per-tool definition and response cost in ≈ tokens, usage by hour or day, and the server version and tool-list hash (scope `admin` or `audit:read`). An `admin` token can now also read the audit log.
- Reports (org, product, release readiness, feature), case search by text and tag, and all-or-nothing CSV import/export of cases with a `version` column. Their 8 operations are MCP tools (90 in all; the default toolsets now list 27).
- Release report: one row per release feature, including features with no cases; each row has `in_release` and `ready`, cases outside the release get their own `in_release: false` rows, and a release is not `ready` while a release feature has no case.
- Tests run on Test Junkie (`test-junkie==0.9a8`), not pytest, locally and in CI: one suite per file, on SQLite and, with `TJ_TCMS_TEST_POSTGRES_URL` set, Postgres.
- Case import takes an optional `mapping` from your CSV's column names to ours, and `format: "md-bundle"` exports and re-imports cases as a zip of Markdown files, one per case; over MCP a zip arrives as `{content_type, base64}`.
- `CHANGELOG.md` merges as a union (`.gitattributes`), so branches that each add a line here no longer conflict.
